Study note 02 · DBMS

DBMS keys,
explained clearly.

Keys help identify rows in a table and connect related tables. The key idea is uniqueness: which attribute or combination of attributes identifies a record?

Beginner levelDatabase conceptsRevision note

1. Super key

A super key is any set of one or more attributes that can uniquely identify a row in a table. It may contain extra attributes that are not needed for uniqueness.

For a Student table, if StudentID is unique, then both {StudentID} and {StudentID, Name} are super keys.

2. Candidate key

A candidate key is a minimal super key. It uniquely identifies a row, and no attribute can be removed from it without losing that uniqueness.

Every candidate key is a super key, but every super key is not necessarily a candidate key.

3. Primary key

The primary key is the candidate key selected as the main identifier for a table. A primary key must be unique and cannot contain NULL values.

CREATE TABLE Student (
    StudentID INT PRIMARY KEY,
    Name VARCHAR(80),
    Department VARCHAR(30)
);

4. Alternate key

Candidate keys that are not selected as the primary key are called alternate keys. They are still possible unique identifiers for the records.

5. Foreign key

A foreign key is an attribute or set of attributes in one table that refers to a candidate key—commonly the primary key—of another table. It helps maintain referential integrity between related tables.

CREATE TABLE Enrolment (
    EnrolmentID INT PRIMARY KEY,
    StudentID INT,
    FOREIGN KEY (StudentID) REFERENCES Student(StudentID)
);

6. Quick comparison

  • Super key: uniquely identifies a row; extra attributes are allowed.
  • Candidate key: minimal super key.
  • Primary key: selected candidate key for the table.
  • Alternate key: candidate key not chosen as primary.
  • Foreign key: references a key in another (or sometimes the same) table.
Check your schema before choosing a key. An attribute is only a key when the data rules guarantee the required uniqueness.
